# PROBE_AND_VERIFY_PLAYBOOK — 探测与验证作业手册

> 定位：**guidance**，不建立新 authority、不改 L0/协议。与 L0 或现行 PROTOCOL 冲突时以它们为准。
> 来源：HT #10 工头 2026-10-22/23 两轮实测（支付宝账单页 / 千牛客户端 / 淘宝工作台），经验经架构复核并更正。落地实现在各项目仓，本文只留方法。

## 0. 一句话

> **先清点既有来源，再考虑新采集；先跑正控，再解释 0。**

实测成本差距全部来自顺序，而不是工具能力：先盘点既有本地产物 ≈10 分钟直接解决"某时间窗没有数据"的疑问；先自建浏览器探针 ≈40 分钟仍未取得目标计数。

## 1. 路线决策表

| 情形 | 先做 | 不要先做 |
| --- | --- | --- |
| 声称"某时间窗没有数据" | 盘点**已存在**的导出件/账单/封存响应，比结构、状态集合与主键集合 | 直接去平台抓 |
| 得到 0 匹配 | 五槽位分诊 + 已知答案正控 | 把 0 写成"不存在/无业务关系" |
| 需要平台侧某时间窗计数 | 识别依赖 → 选传输 → 现场回执（§6） | 自建探针 / 绕过站点拒绝 |
| 要发布只读回执 | 发布卫生闸（§5） | 手工扫一遍就发 |
| 结论要进 durable | 只放计数/哈希/分布/标签/指针 | 放原始行、金额、长 ID |

## 2. 零结果五槽位（缺一即 UNKNOWN）

报告任何 0 之前逐槽位回答，并留下证据指针：

1. **SCOPE**：数的到底是哪个总体？（文件、时间列、状态集合、账户范围）
2. **CONTROL**：同一套机器在**已知有答案**处能否产出非零？（没有正控的 0 不可解释）
3. **NAMESPACE**：哪些标识符配对在语义上成立？（同名/同格式 ≠ 同实体）
4. **COVERAGE**：总体完整性是否被独立证明？（子集行数 ≠ 平台口径）
5. **VISIBILITY**：0 是否由**机制**解释？（如担保交易未结算 → 账单无结算行）

> 三个"0"必须分开：**来源筛选造成的 0** ≠ **总体缺失** ≠ **可解释的 0**。三者所需证据不同。

## 3. 零捕获必须 fail-closed（采集层）

- 观测工具捕获 0 条时，先排除**测量器自身**：事件是否 enable、目标是否正确、窗口是否够、类型/URL 过滤是否过窄、是否有已知正控流量。
- 未排除前只能记 `CAPTURE_UNKNOWN` / `PARTIAL` / `OBSERVATION_INCOMPLETE`，**不得**记 `COVERAGE_COMPLETE_FOR_SCOPE`，更不得据此断言"对方没有接口"。
- 已知坑：CDP `Network.requestWillBeSent.params.type` 首字母大写（`XHR`/`Fetch`），小写比较会**静默零捕获**。

## 4. 三路互证

同一输入至少两条**实现不同**的读取路径，关键量（行数、分布、ID 计数）一致才进结论；外部执行体产出的代码**不因"测试通过"而可采信**，必须与宿主实现互证。

## 5. 发布卫生（只读回执）

- `safe` = 计数、哈希、分布、标签、指针；**不含**长 ID、金额明细、客户字段、绝对路径。
- 业务标识只**遮蔽**，不进 allow-list；allow-list 只留给"按惯例已公开"的指针，且逐条写明理由。
- **检出器自身不得回显完整命中值**（只给掩码与长度），否则它成为新的泄漏点。
- **作用域**：闸门针对**新产出的回执**；既有运维文档里 owner 记录的来源目录/主机名只报不改，是否调整由该文件 owner 决定。
- **元规则：会误报的闸门最终会被绕过。** 每个检测器都要对本仓已公开的真实产物跑回归；误报用规则修正 + 回归测试钉住，不要用 allow-list 长期掩盖。

## 6. 传输选择：三步，而不是"有无签名"

1. **识别依赖**：签名（`sign`/`t`）、会话（cookie/token）、CSRF、动态参数（nonce/时间窗）、服务端状态（导出任务/分页游标）、账户权限。
2. **选传输**：依赖可由受支持 HTTP 路径满足且属授权范围 → 可构包；依赖由页面自身计算/注入 → **在已授权页面上下文内完成操作**（调用页面自身 SDK），不导出令牌、不离线重放。
3. **现场回执验证**：以状态、结构、行数、分页终态留证。**一次成功不外推到其它账号/路由/时间窗**；任何传输选择都**不得用于规避站点/tool 访问拒绝**。

> 签名只是**路由线索**，不是授权，也不是通用重放保证。

## 7. 共享工作树并发纪律

- 唯一可写树与被冻结树分工固定；**按路径提交**（`git commit -- <paths>`），禁止 `git add -A`。
- 不带走、不清理、不重排他人的 staged 改动（对应 L0 §3）。
- 提交后 `git show --stat` 复核只含本工单文件。

## 8. 外部执行体（模型/工头）边界

- 只给**通用合同 + 合成夹具**；真实行、真实 ID、凭据不出本机。
- 验收：真实数据由宿主脚本跑；外部产出须与宿主实现互证；未互证部分不计入结论。
- 留痕：session id、完整命令、exit code、测试数与真实结果、产出文件 SHA-256。

## 9. 有界现场观察

- **前提是授权**：Human 明确提供浏览器/凭据/范围方可进行；录制窗口由 Human 控制 Start/Stop。
- 站点安全拒绝不是可绕过的连接故障；换工具/换账号/换环境规避 = 违规。
- 输出只允许聚合值；**点击白名单**使副作用控件物理上不可点；不翻页遍历；不点导出/发货/退款/改价；结束后恢复现场并复核。
- **先证明动作到达了目标**（`elementsFromPoint` / 栈顶 / `pointer-events`），再用可观测状态证明生效；只有"动作到达 + 状态未变 + 无请求"三者同时成立，才可判定对方不响应。

## 10. 口径（避免过度声明）

- 读进内存 ≠ 持久化：正确表述是 `NO_ROWS_OR_ACCOUNT_VALUES_PERSISTED`，不是"从未接触响应内容"。
- 派生结构表（Representation）≠ 原始响应体 / wire bytes / 字节级覆盖预检；需要字节级证据时另以 `RAW_CAPTURE` 保留 + SHA-256 + provenance。
- 平台页签计数 ≠ 时间窗计数 ≠ 导出行数：不可互相替代，也不可用任一方推断另一方。
