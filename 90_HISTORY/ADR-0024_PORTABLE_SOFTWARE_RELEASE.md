# ADR-0024 — 将标准发行与可移植部署纳入既有工程原则

- 状态：Accepted — Human 于 2026-11-20 明确要求，见 [#193](https://github.com/youling/ai-use/issues/193)；是否进入正式规范以该工单关联 PR 的合并状态为准。
- 变更等级：L2；延续 [ADR-0021](ADR-0021_ARCHITECT_ENGINEERING_AND_STAGE_DIAGRAMS.md)。
- 当前原则唯一入口：[软件架构与工程实践 §2.1](../30_PROTOCOLS/SOFTWARE_ARCHITECTURE_PRACTICE.md#21-标准化软件发行与跨节点可移植性)。

## 背景与决定

既有工程实践已明确高内聚、低耦合，但运行环境变化如何影响软件发行仍缺少跨技术栈的共同表述。单个节点能运行，不能证明新增兼容节点只需部署；OCI 的具体合同也不应代替所有产品的发行原则。

因此在现有工程实践中补充一个短节，将职责边界延伸到制品、环境输入与生命周期，按真实证据界定兼容范围。阅读路由增加发行与部署场景，具体实现和接受标准仍由各项目负责。

## 取舍与影响

保留制品身份、环境隔离和证据诚实等必要不变量，同时让项目按实际风险选择打包、适配和验证方法。没有采用统一容器化、固定双宿主测试、每个例外另建 ADR 或先完成全仓治理再上线的方案，因为它们可能增加交付成本，却不能自动证明可移植性。

现有 OCI 合同继续拥有 OCI 身份与验证细节；本次不修改它，也不建立新的审批角色、生命周期或并行手册。存量代码沿原 owner 与工单增量收敛，不追溯改变当前工作验收。后续调整按新 PR 留痕，保留本次裁决历史。
