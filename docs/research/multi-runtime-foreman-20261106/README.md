## 3. 运行器接入先跑小探针

下图是**派单前的观察顺序**，不是新的 Work 状态机，也不要求重复已存在且仍有效的证据：

```mermaid
flowchart LR
    A["本版程序与入口"] --> B["本路径的身份/可用模型"]
    B --> C["无副作用的真实模型回复"]
    C --> D["受限工具/文件 canary"]
    D --> E["实际产物与回读"]
    E --> F["接入当前 Work 的有界执行"]
```

- 程序存在、`--version` 或 capabilities 成功，只证明入口/元数据的一部分。不要根据可用模型列表推断模型请求能成功。
- 本例 ZCode 桌面版本与 bundled CLI 版本不同；普通 CLI、TUI、app-server 是不同入口。TUI 缺包、模型未选择、空会话可创建各有不同含义。此处记录历史观察，不把这些接口/错误当未来版本契约。
- 桌面已有账号和选择，不证明独立 CLI 已获得相同 host provider 上下文。不得靠读取密钥、伪造 entitlement/header 或修改安装 bundle 解决接入。
- 免费资源、账户授权、原生工具权限、Host 网络边界和工程权限分层核实。有额度不意味着有容量、所有模型可用或有执行权限。
- 第一轮无模型回复时就留精确缺口；不要让可用的 Android/iOS 路线等待一个尚未合格的备用执行器。
- 原 CLI 参数和模型 effort 随实际版本查证。旧示例是历史，不是可直接复制的当前命令。

## 4. 失败分类和恢复动作

| 观测 | 有信息增益的下一步 | 本例的证明边界 |
|---|---|---|
| 免费路线 HTTP 429 / free-limit | 保存已完成产物和未提交状态，保留原错误；仅使用已授权且实际可用的另一执行路线，或等待当前窗口 | 只证明该次请求被限额，不证明所有免费路线均耗尽 |
| outer network / proxy socket 拒绝 | 核对错误所属层；在已有授权内走允许的网络执行环境，保留原失败 | 本例后来执行了采集脚本，但脚本自身前台检查仍未通过，网络恢复不等于目标成功 |
| headless read/write/command 被拒 | 核对实际动作、目标与已有授权；修正不匹配或缺失的窄规则时记录依据；真正越界则只阻断该动作 | 不换工具/复制被拒资源来绕过裁决；不以全权限开关代替调查 |
| SUCCESS 但无 response 或带 denied_actions | 读实际工件/测试和工具回执；未产出即未完成 | 本例有同一会话被允许的两次读取后，第三个读取仍失败；不能把进程零码当全路径已授权 |
| SSH 签名失败，随后本机 GUI 构建成功 | 分别记录认证、团队、证书、钥匙串提示、本机构建与远程签名证据 | 不据 GUI 成功宣称 SSH 签名已修复，也不能凭一个错误码锁定唯一原因 |
| 前台窗口检查无匹配 | 停止未知应用截图，记录未确认；把设备/窗口问题交原执行线核查 | 不是 App 崩溃证明；历史截图标历史，不冒充新拍 |

授权已覆盖的普通恢复不应反复请 Human 确认；新增持久认证、平台要求本机本人操作或真实高风险动作仍按当前边界处理。自动审批拒绝、运行器 headless 拒绝和操作系统授权提示必须分别说明，不能笼统称为“用户没授权”。

## 5. 接续、并行和最小交接包

本次有效的恢复单元是**同一 Work 的当前候选与证据**，不只是会话 ID。建议在中断或换执行器时提供：

1. 目标、当轮阶段与当前不做的工作；例如 Human 已改为“先测试收集，后集中修复”，旧实现权限不能覆盖新阶段。
2. source commit、已知 dirty 文件/补丁与未跟踪清单、最后产物 hash、最后测试状态。先确认旧 writer 已停或交接，不把新的 worker 同时放进同一写域。
3. 少量必要输入的可读指针与范围，读/写集合、共享设备/缓存和原拒绝；不复制整段聊天或凭据。
4. 每个下一步的成功产物和停止条件；不是只写“继续加油”或“处理好所有问题”。
5. 运行器原生 ID、模型请求与实际观察、已知工具限制保留在实例 owner；公共经验不复制这些私有事实。

Android 和 iOS 可并行处理平台工程、设计可并行做原型、AI/富文本可分别只读研究。共享核心、同一设备安装/采集、同一浏览器窗口及验证产能则约束并发。没有实际监督进程/服务证据，不承诺聊天结束后自动续跑。

本次跨对话设计协作采用“GitHub Work → 明确授权消息 → 对方 GitHub 接单 → 精确版本交付与回读”。工具投递返回、网页显示处理中、报告自称完成均不能替代对应证据。已经有 GitHub 文件的交付，不再强迫建立第二套本地状态数据库。

## 6. 产品验收：每一层只证明自己

本例共享静态分析成功，单元/组件回归 **100 PASS / 1 SKIP**；跳过的是可选真实站点检查。它不证明真实登录、AI 报告或视频已可用。代码核查发现这些接入仍有缺口，所以保留为待修需求，不能把验收改成“游客 App 已够用”。

```text
可构建 → 可安装 → 进程启动 → 首屏可见 → 目标内容可读
       → 真实账号会话 → 用户动作与反馈 → 跨端/离线/媒体/性能
```

这是验收维度示意，不要求每个项目机械全做。用户需求决定哪些维度必要；不同维度各自给证据。

- 启动器 Activity 耗时不等于“最新文章已经可读”。首屏旧缓存先出现再变新，需要内容身份和时间序列证据。
- 局部帧样本没有超预算，不能宣布全场景不卡。保留异常批次、设备刷新率、构建模式、滚动路径与缓存条件。
- HTML 原型的几何/字号/状态测试不替代 Flutter 原生 TextScaler、读屏、真慢网或解码/内存测试。
- 有 AI 界面或本地 report schema 不等于真实模型服务已接通；有外链按钮不等于嵌入视频播放成功。
- 用真实公开内容、无图/多图/视频等反例检验需求。素材与客户端状态分开，不能用漂亮模拟数据掩盖实现缺口。

## 7. 研究质量与时间成本

AI 研究第一稿曾把未核实的价格/免费期限写成事实，并错误排除原生 CLI 自动化；富文本稿曾过度推断竞品实现。根将关键主张退回，要求直接来源与未知分列。这是**已发现并部分修正的研究质量问题**，不是已经完成模型选型或真实端到端验证。

复核优先级建议：会改变路线的事实 → API/合同细节 → 成本/容量 → 引用完整性。资料结论、建议架构、真实样本质量、持久化读写和上线状态分别给标签。供应商客户端内生成并导出报告，与将其受限端点代理给全部读者，是不同问题，不能用一个结论同时覆盖。

时间账本最低可记录：调度发出、实际开始、关键产物、阻塞/恢复、有限阶段终止的 wall-clock 时间与时区。有效工作时间使用区间并集，不把并行 worker 时长相加当用户等待时间。暂停和下载/签名/额度等待是否计入，先说明口径。原生 result 的 duration/usage/turns **可能是 resume 累计**；本轮未建立完整增量账单，不报精确总 token/费用，也没有支持普遍提速倍数的对照试验。
