# Antigravity 工头后续：空 SUCCESS、位置隔离与失败控制

分类：NON-NORMATIVE / QUALIFIED_SYNTHETIC_ONLY。延续本目录既有运行记录；只保存本轮观察，不修改公共协议或提供全局保证。

## 接入既有工头模式的注意事项

按需启用工头、工头协调架构师与子对话并负责回写，直接沿用 [Foreman 合同](../../../20_ROLES/FOREMAN.md)。本记录只补充 Antigravity 的运行观察和使用注意事项，不重写角色或调度规则；本轮两个原生子对话是历史试跑参数，不是后续人数上限。

- 全局 settings 与任务参数分别核对，试跑不要顺手切换全局 provider、登录方式或付费设置。若确需恢复配置，保留其它字段，并检查写入前变化。
- 显式请求模型、child inherit、实际执行后端和额度归属分开记录；宿主平台另外启动的子上下文不算 Antigravity 原生子对话。
- 外层空 SUCCESS 时，先核对原生子状态、实际制品和验证回执，再按实际 conversation 恢复；同一会话续跑不计为新工头或新子对话。
- 原生 branch 要核对实际物理目录与冻结输入，不能仅凭 branch 名称判断隔离；原始会话和思考保留本机。
- CLI 能产生文件或调用工具，不证明 GitHub 写入连接已可用；回写与回读继续由现行合同中的责任方通过已验证路径完成，原生能力未验证时如实标注。

CLI 1.3.4 本轮显式请求 Gemini 3.8 Flash High / high，工头创建两个原生 branch 子上下文。宿主独立核对其首读完整 kernel、物理目录与 branch 不同、冻结输入字节没有漂移。子任务分别实现窄辅助工具及独立编写合同测试；后续宿主审查和新的独立上下文补充攻击控制。这样的隔离防止互相覆盖，并不自动证明模型行为或制品正确。

三次工头调用的外层 result 都是 SUCCESS，但 response 为空，其中两次约 367 秒后结束打印窗口。子文件实际上已产生，宿主能够冻结并执行；外层 SUCCESS、文件存在、子任务状态和完整工头 final acceptance 是四种不同事实。不能只凭退出码或 result.status 宣称最终验收，也不能反向把空 response 等同所有子任务没有工作。保存每次边界、文件 SHA 与实际复现回执，再决定是否需要同会话恢复。

CLI 请求模型和 child inherit 是已观察的配置。child 实际后端与独立账单归属仍未观察；本轮没有主动切换其它模型、回退提供方或修改 overage/global settings。宿主另外启动的独立编码/验证上下文应记录其所属执行平台，不能混入 Antigravity 的模型额度推断。缺少 provider 侧账单时，不从 token 估计、累计统计或 UI 百分比推导付款及免费额度保证。

本轮发现一个可迁移的接口教训：给捕获换一个 producer 名称，不一定隔离扫描位置。必须回读底层实际 key 轴。辅助执行最终选择独立 capture 扫描台账，而保持逻辑来源代次字段；捕获内容身份不冒充 native 身份。另一个缺口是可变索引与回执能够协同改动，二者互相验证不能代替对冻结计划的验证。宿主在隔离副本中修正唯一的内容推导规则，独立攻击控制证明旧版可接受协同改动、修正版拒收；不以之前的绿测代替新发现的证明义务。

测试作者的隔离同样需要公共 API 合同。一次补充测试把 keyword-only 参数当位置参数，导致两个版本都在 setUp 阶段报错。宿主提供的最小签名漏了星号，已保存首次代码/流并补齐签名，原攻击与正向断言逐字保留。这种双错误不是语义 RED/GREEN；只有初始化通过、正向读取成立、旧版未拒收及修正版确实拒收，才形成有效对照。另一次历史合成 fixture 使用未登记的原件指针，严格校验拒收；补正指针的控制与未修改原测试的失败分别保存。

失败控制以原因和源码版本为单位保留，不为了表面全绿取消断言：错误预期、实现缺口、未满足的新合同、权限跳过、输出窗口及类型错误分别有 recoverable pointer。测试或源码复审暴露的新义务可以窄修正，但要先冻结验收变化、保留旧稿，不能由实现者现场自造可通过标准。

Windows 的真实 symlink 创建权限本轮不满足，两项执行被 SKIP。源码中的 link/reparse 判断、平台权限和成功创建链接后的运行实验不可互相替代。受控合成扫描、磁盘重载、复制时哈希、复制后 stat，也不能推广为 active WAL、并发敌手、真实长期增量、断电或消费者持久化保障。

发布阶段 expected-main 守卫捕获主干前进，实际未向旧基线写入。宿主逐项比对所用源码 Git blobs 与新主干，确认相同后才以新基线建分支，并在新主干真实执行相关门禁。经验是保留“测试时源码版本”与“发布时仓库基线”的两条证据，而不是覆盖历史 ref，或在只变其它范围时无依据宣布必须推翻全部实验。
